# Market Intelligence — окрема версія (MVP)

Це **нова незалежна програма** у GitHub-гілці `market-intelligence-v1`, не редизайн старого торгового термінала. Попередня гілка `redesign-approved-trading-ui` лишається без змін.

## Швидкий запуск на Mac

Найпростіше зробити окреме робоче дерево, не перемикаючи стару програму:

```bash
cd ~/Desktop/ai-trading-assistant
git fetch origin market-intelligence-v1
git worktree add --track -b market-intelligence-v1 ~/Desktop/market-intelligence origin/market-intelligence-v1
cd ~/Desktop/market-intelligence
node market-intelligence/server.mjs
```

Якщо локальна гілка з такою назвою вже існує, використовуй `git worktree add ~/Desktop/market-intelligence market-intelligence-v1`. Адреса програми: http://127.0.0.1:4188/ . Node.js 22+ рекомендовано.

Програма не потребує npm install і не змінює попередній сервер на порті 4177. Для оновлення в окремій папці: `cd ~/Desktop/market-intelligence && git pull --ff-only origin market-intelligence-v1` (перезапусти Node-сервер після оновлення).

## Мета та поточні можливості

- **Можливості:** одна найкраща **свіжа та підтверджена** торговельна пропозиція за даними Bybit Public. Entry, Stop Loss, Take Profit, R:R і короткий опис причин.
- **Спостереження:** ліквідні криптоінструменти без готових умов входу. Не підміняються сигналами.
- **Мої плани:** локально збережені рівні (браузерний localStorage), **не** реальні біржові заявки, не синхронізуються між браузерами.
- **Аналітика:** критерії оцінки й обмеження.
- **Підключення:** форма Demo API Key / Secret та перевірка облікового запису з macOS Keychain.

## Джерела та ринки

На цьому етапі **фактичні сигнали працюють лише для криптовалют** через публічний API Bybit. Акції/ETF, Forex і сировинні активи показані як **ще не підключені**. Не видаємо вигадані котирування або готові плани для недоступних ринків.

Сканер відбирає до 16 найбільш ліквідних USDT perpetual і застосовує власний локальний модуль `market-scanner.mjs` для чотирьох таймфреймів (15м, 1г, 4г, 1д). Кожна пропозиція перевіряється на актуальність (не старша за 20 хвилин). Сканування відбувається приблизно раз на 10 хвилин під час роботи локального сервера. Тимчасові відмови Bybit, включно з HTTP 429, повторюються з обмеженою експоненційною паузою; фінальний звіт зберігає символ і причину, якщо дані не вдалося отримати.

Сортування за підтвердженнями, R:R та ліквідністю — **це не ймовірність прибутковості**. Правила можуть помилятися; незалежний довготривалий backtest і paper trading залишаються обов'язковими перед реальними угодами.

## Bybit Demo

1. Створи **окремі ключі Demo** в самому Bybit із правами *read-only*, якщо доступно.
2. Відкрий у новій програмі **Підключення**, введи Key і Secret.
3. Локальний сервер перевірить пару запитом до `https://api-demo.bybit.com/v5/account/wallet-balance`.
4. Після успіху обидва значення зберігаються **лише в macOS Keychain** під сервісами `com.market-intelligence.demo.api-key` та `com.market-intelligence.demo.api-secret`. Ці сервіси не перезаписують ключі старої програми.
5. Програма дозволяє лише **перегляд** Demo-балансу, позицій та ордерів. **Жодних endpoint'ів для створення, редагування чи закриття ордерів немає.**

Ключі **ніколи не вводяться у ChatGPT**, не зберігаються в GitHub, HTML-файлах, браузерному localStorage або репозиторії. Для підключення потрібна саме локальна програма на Mac, не GitHub Pages. З'єднання доступне тільки на 127.0.0.1; сервер перевіряє Host/Origin, використовує CSP та не повертає самі секрети клієнту.

## Перевірки

```bash
node --check market-intelligence/server.mjs
node --check market-intelligence/app.js
node .github/scripts/check-market-intelligence.mjs
```

Smoke test працює без реальних API-ключів та без мережевих запитів до Bybit. Він перевіряє запуск, ізоляцію UI, недоступні ринки, блокування чужих Origin і відсутність API для відкриття угод.

### Що залишилося перед повноцінним продуктом

- Підключити й перевірити постачальників котирувань для акцій, Forex і сировини, включно з ліцензіями та торговими сесіями.
- Провести окрему перевірку точності сигналів, статистичну калібровку та вперед-орієнтоване paper trading.
- Додати перевірку виконуваності ціни входу, спреду, funding, комісій, ковзання і ризику портфеля.
- Реалізувати обмеження API, backoff та відновлення після довгих збоїв.

Це перша **signal-first** версія, а не система з гарантованими торговими сигналами.


## Двоступеневий відбір кандидатів (v1.2)

- **Якість ринку**: окрема оцінка 0–5 за EMA, RSI, MACD, обсягом та узгодженням трендів. Це не прогноз імовірності прибутку.
- **Придатність угоди**: перевірка напрямку, коректної геометрії Entry / SL / TP, ризику до SL не більш ніж 5%, валового та **модельного після витрат R:R ≥ 1:1,5**, мінімального добового обігу 10 млн USDT і відстані від останньої ринкової ціни до умовного входу. Поріг ліквідності — консервативний параметр MVP, не оцінка глибини стакана.
- Для модельних витрат використовуються **0,055% комісії + 0,05% прослизання на сторону**, а не фактичні тарифи рахунку. Спред, funding і поведінка виконання в реальному стакані **не перевірені**. Високий бал індикаторів за недостатнього R:R не створює готової пропозиції.
- **«Близько до входу»** означає лише одну відсутню ринкову умову за прийнятної розрахункової геометрії, ліквідності й ціни; це ще **не сигнал**.
- **Попередній сценарій** у вікні деталей показує умовні Entry / SL / TP тільки за коректних базових рівнів. Це не ордер і не команда купувати/продавати.
- Готовий план блокується, якщо ціна з відкритого тікера відійшла від еталонної закритої свічки понад адаптивний допуск (половина ATR, але від 0,2% до 1%). Цей контроль не замінює перевірку актуальної котировки безпосередньо перед угодою.
- Гілка `redesign-approved-trading-ui` не змінювалася. Відправлення реальних ордерів залишається вимкненим.

**Наступна вимога до якості:** незалежний backtest і forward paper trading для перевірки того, чи новий рейтинг справді покращує результати. Поточний рейтинг не має підтвердженої прибутковості.


## Forward Paper Trading (новий модуль)

У розділі **Аналітика** відображаються реальні *майбутні спостереження* за новими підтвердженими планами, які виникли під час роботи локального сканера. Це **не** ретроспективне моделювання історичних сигналів і не виконання на Bybit Demo.

- Після сканування кожні ~10 хвилин сервер реєструє підтверджені плани `Entry / SL / TP`.
- Умовний вхід фіксується **не раніше початку наступної годинної свічки після реєстрації сигналу**. Для перевірки використовується лише вже закрита 1h свічка. Ніяких фактичних ордерів у Bybit немає.
- Для результату використовується консервативний пріоритет **Stop Loss над Take Profit**, якщо обидва рівні перетнули одну годинну свічку. Розрив ціни через стоп моделюється за гіршою з цін: Open чи SL.
- Припущення витрат: комісія 0,055% на кожну сторону, несприятливе прослизання 0,05% на сторону. Funding, біржовий спред, ліквідація та реальне виконання в стакані не змодельовані.
- Якщо між перевірками пропущена необхідна годинна свічка, результат позначається `unverifiable`, а не «перемога».
- Програма не відкриває повторних записів для того самого активного сценарію і використовує 4-годинний захист від швидкого повторення.
- Поки немає завершених умовних угод, Win Rate, Profit Factor та інші залежні від вибірки показники мають значення «—».
- Результати зберігаються в `~/Library/Application Support/Market Intelligence/forward-paper.json` із локальними дозволами. Вони не публікуються в GitHub і не містять Demo API-секретів.
- Ключі Bybit Demo залишаються у macOS Keychain і використовуються виключно для read-only перегляду рахунку.
- Журнал працює, лише коли локальний Node-сервер виконує сканування. Під час його простою нові сигнали не створюються, а відсутні свічки не відновлюються здогадами.

Тести: `node .github/scripts/check-market-forward-paper.mjs`. Перевіряють відсутність вигаданих результатів, persistence, SL-first, моделювання витрат, пропущені свічки й захист від дублікатів. **Ці тести перевіряють програмну логіку, а не прибутковість стратегії.**

Наступний окремий етап: історичний backtest із відповідним обліком обсягу, ліквідності, моменту появи сигналу та незалежної перевірки; його не слід підміняти вже наявною forward-статистикою.


## Затверджена політика керування ризиком

- Максимальна **модельна втрата на одну нову позицію — 1% від актуального `totalEquity` Bybit Demo**.
- Максимальна **сукупна модельна втрата для відкритих позицій і нової позиції — 3% `totalEquity`**. Береться менша величина між 1% капіталу й залишком 3%-го бюджету.
- Це окремі величини: **R:R — відношення потенційного прибутку до ризику**, а 1% — грошовий бюджет допустимого збитку. Кількість інструмента = доступний ризик / ризик одиниці з урахуванням модельних витрат.
- Відкриті лінійні позиції враховуються за `avgPrice`, `size`, `stopLoss`. Якщо позиція не має коректного SL, дані рахунку неповні, є активні заявки чи немає чинного Demo-балансу, розрахунок **блокується**.
- Враховується 0,055% комісії й 0,05% прослизання на сторону лише як припущення. Розрахована кількість **не округлена до біржового кроку**. До виконання ордерів треба врахувати мінімальний лот, доступну маржу, ризик інших категорій рахунку, інші заявки, валюту номіналу, справжні витрати і захист від прослизання.
- Навіть з цією політикою реальний збиток може перевищити 1% через гепи, проскальзування, ліквідацію або відмову Stop Loss. Це обмеження планування, а не гарантія.
- `GET /api/risk/policy` показує ліміти, а `GET /api/risk/plan?symbol=BTCUSDT` оцінює **виключно актуальний, підтверджений сервером** план за **read-only** Demo API. Ключі не передаються клієнту.
- Новий блок у деталях готового плану показує капітал, зайнятий і доступний ризик та максимальну розрахункову кількість. **Ордери вимкнені.**
- Акції, Forex, сировина й інші біржі потребують окремого адаптера рахунків і портфельного ризику. Поточна перевірка покриває лише отримані з Bybit Demo USDT linear-позиції; за відсутності підтвердження всього портфеля реальні угоди недопустимі.
